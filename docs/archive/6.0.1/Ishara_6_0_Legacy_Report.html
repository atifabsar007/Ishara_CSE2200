01 / Project Overview

Abstract and problem statement

Abstract. Ishara is a Java-based Android accessibility prototype that helps people communicate using a small recognized gesture vocabulary, readable text, text-to-speech, and supportive communication tools. Its main interaction is to recognize a handshape through the phone camera, show the assigned demonstration meaning, combine words or phrases into sentences, and speak the completed message.

Problem statement

People who cannot speak easily, people using gestures, and people with hearing difficulties can face barriers during everyday communication. Many listeners do not understand another person's hand signals; typing can also be difficult in time-sensitive interactions. A low-cost, approachable tool is needed to support clearer two-way communication.

Objectives

  • Recognize predefined hand gestures locally through an Android camera.
  • Convert recognized gestures to readable Bangla demonstration phrases and spoken output.
  • Combine recognized words/phrases into an editable sentence.
  • Offer live captions, visual communication boards, saved phrases, and offline practice.
  • Demonstrate real Java Android programming concepts across laboratory Weeks 8–11.
Core principle
Gesture Camera → Detected Handshape → Bangla Demo Meaning → Editable Sentence → Speech

Primary users

People with speech-related communication difficulties; people who prefer gesture-assisted communication; deaf or hard-of-hearing users who benefit from text captions; and family members, caregivers, and others communicating with them. Classroom use is an additional scenario, not the application's primary purpose.

02 / Proposed Solution

Solution and application workflow

Ishara combines Android CameraX with the MediaPipe Gesture Recognizer. A pretrained model returns recognized general handshapes and hand landmarks. Java translates these categories to transparent, predefined demo phrases. Users can confirm, correct, combine, speak, save or share messages.

CameraX live video → MediaPipe on-device gesture classification
↓
Confidence + 21-point landmark visualization + calibration threshold
↓
Gesture Dictionary / correction log / context-specific demo mapping
↓
Java rule-based Sentence Builder → TextToSpeech / Save / Share / Peer Link

Complementary communication flow

Microphone → Android SpeechRecognizer → Live Captions / Two-way conversation → SQLite caption history → Search / Share.

Design principles

Accessible: large buttons and legible text. Local-first: recognition and most phrase operations happen on the device. Understandable: users see which handshape was recognized and can correct errors. Lab-oriented: the code includes explicit Activities, adapters, custom Views, SQLite operations, Services, Intents and networking examples.

Scope note: This version is not a complete Bangla Sign Language translator. It recognizes seven general handshapes and assigns illustrative phrases. Actual sign-language support requires separate labeled data and evaluation with knowledgeable signers.

04 / Technology and Architecture

Implementation design

Programming stack

  • Java 17: Activities, object-oriented classes, algorithms, input validation and event listeners.
  • XML: screen structure and accessible UI components.
  • CameraX / MediaPipe: live frame input, category labels and 21 hand landmarks.
  • TextToSpeech / SpeechRecognizer: spoken messages and live transcripts.
  • SQLite: message history, practice records, game progress and user corrections.

Supporting libraries

  • RecyclerView: visual dictionary, history and chat cards.
  • Material Components: clean UI controls and feedback.
  • Intents, Services, Receivers, ContentProvider: Android component communication.
  • HTTP / JSON, optional Firebase: network demonstrations.
  • Java Sockets: same-Wi-Fi Peer Link prototype.

Local data model

Data areaImportant fields / purpose
MessagesText, type, timestamp; saved communication and history.
CaptionsSession title, transcript body, language, timestamp.
Gesture practiceExpected class, detected class, confidence, outcome, timestamp.
Gesture correctionsPredicted class, corrected class, confidence, timestamp, separate database.
Phrase usagePhrase, category, usage count; adaptive shortcuts.
Profiles / gamesLocal login data, quest scores, scenario progress.

Sensitive conversation records remain on-device by default. Optional network and Firebase modules require extra setup. Local accounts are not remote authenticated cloud accounts.

07 / Evaluation and Future Scope

Testing, limitations and conclusion

Testing plan

  • Build the Android Studio project with SDK 35 and Gradle JDK 21; verify installation and all navigation routes.
  • Use a physical Android camera to evaluate all seven gestures in multiple lighting conditions. Record confidence, false positives and corrections.
  • Build the message “আমি পানি চাই” in the Sentence Builder, apply the rule suggestion, save and speak it.
  • Test dictionary search, adjustable thresholds, landmark overlay toggle and database persistence after restart.
  • Test microphone permissions and Live Captions in Bangla and English with an installed speech recognition service.
  • Test login, local data isolation, saved history, Quest and optional Peer Link on two devices.

Limitations

The stock model recognizes only seven general handshapes. Calibrating thresholds does not retrain the neural network. The 21-point overlay is an approximate visual aid that requires physical-device alignment testing. Continuous captioning and Bangla speech output depend on device services. Peer Link is an unencrypted local demonstration. The project source passes static checks, but a full Android Gradle build and usability evaluation have not been completed in this report environment.

Conclusion

Ishara demonstrates how Java-based Android programming can support practical, more inclusive communication. Its main contribution is a transparent gesture-to-message workflow supported by sentence composition, speech output, visual learning and calibration. Its secondary modules broaden accessibility while providing demonstrable examples of the full laboratory syllabus.
